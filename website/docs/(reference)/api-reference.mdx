## Rehype pass

Import from `quickinfo/rehype`.

### rehypeQuickinfo

The rehype pass. Stamps `data-api-id` onto prose mentions of API symbols at build time: inline code, and links to API pages. A mention annotates only when it resolves to one symbol; a link to an API page names its symbol even when the bare name is ambiguous.

```ts
rehypeQuickinfo(options?: RehypeQuickinfoOptions): (tree: Node, file?: PageFile) => void
```

#### Parameters

<TypeTable type={{
  "options": {

    "default": "{}",
    "description": "Rehype pass options."
  }
}} />

Returns `(tree: Node, file?: PageFile) => void`: The rehype transformer. It annotates nothing when `dataFile` is missing or empty, so a build before the index exists still passes.

```js
const quickinfoRehype = require('quickinfo/rehype');
const dataFile = path.resolve(__dirname, 'generated/quickinfo-names.json');

rehypePlugins: [[quickinfoRehype, { dataFile }]],
```

## CLI

Builds hover data from a built Sphinx or MkDocs (mkdocstrings) site: ids, kinds, and links from `objects.inv`, and signatures, summaries, and base classes from the API pages.

```text
Usage:
  quickinfo build <site-dir> [--out <dir>] [--served-at <path>] [--inventory <file>] [--no-assets]
  quickinfo assets <dir>

build   Write names.json, info.json, and quickinfo.js for a built Sphinx or
        MkDocs (mkdocstrings) site, from its objects.inv and API pages.
        --out        Output directory. Default: <site-dir>/_static/quickinfo
                     when _static exists (Sphinx), else <site-dir>/quickinfo.
        --served-at  Where the output is served, relative to the site root.
                     Default: --out's path inside <site-dir>, or its folder
                     name when --out is outside the site (a docs folder the
                     generator copies to the root, like docs/quickinfo).
        --inventory  The objects.inv to read. Default: <site-dir>/objects.inv.
        --no-assets  Skip copying quickinfo.js.
assets  Copy quickinfo.js into <dir>.
```

### resolveHref

Extract a symbol id from a link to an API page on the same site. A fragment naming a symbol wins (`graph.html#max.graph.Graph`, the shape Sphinx and mkdocstrings emit); otherwise the page path's last segment names it when it reads as a symbol page: a dotted id (`max.graph.Graph/`) or a Markdown file (`Graph.md`). A plain path segment (`/quickinfo/`, a site's own base path) is a page, not a symbol. Links with a scheme or host (`https://docs.python.org/...#int`) point at another site's symbols and never resolve, and only ids in the index count.

```ts
resolveHref(href: string, index: SymbolIndex): string | undefined
```

#### Parameters

<TypeTable type={{

Returns `string | undefined`: The symbol id, or `undefined` for any other link.
