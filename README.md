# docusaurus-plugin-api-hover

Docusaurus plugin that adds IDE-style API hovers to your docs: identifiers in
code blocks and prose that reference a documented API symbol get a dotted
underline, and hovering one highlights every instance of the symbol on the
page and shows a tooltip with its kind, full name, signature, and a link to
its docs page.

The plugin is generic: it ships the runtime (tooltip, highlight, placement),
a rehype pass for prose mentions, and a Prism token annotator with Python
built in. Your site supplies the symbol index and the info JSON
(signatures/docstrings) — typically generated by a small build script that
knows your API.

## Install

```bash
npm install docusaurus-plugin-api-hover
```

## Usage

`docusaurus.config.js`:

```js
const apiHoverRehype = require('docusaurus-plugin-api-hover/rehype');

module.exports = {
  // ...
  plugins: [
    [
      require.resolve('docusaurus-plugin-api-hover'),
      {
        // Names JSON: { ids: string[], bases: Record<string, string[]>,
        //               version?: string }
        dataFile: path.resolve(__dirname, 'generated/api-hover-names.json'),
        // Info JSON: { [id]: { kind, url, signature, doc } } — fetched at
        // runtime; `version` is appended as a cache-busting query.
        infoUrl: '/data/api-hover-info.json',
        // Id prefixes that win short-name collisions, e.g. a site that
        // indexes both its own symbols and Python stdlib ids.
        preferPrefixes: [],
        languages: ['python'],
      },
    ],
  ],
  // Nightly docs (or wherever markdown is rendered outside the docs
  // pipeline) also need the prose pass:
  markdown: {
    rehypePlugins: [
      [apiHoverRehype, { dataFile: path.resolve(__dirname, 'generated/api-hover-names.json') }],
    ],
  },
};
```

Put the info JSON somewhere under `static/` so it is served at `infoUrl`, and
generate the names JSON before the Docusaurus build (a prebuild step). If
`dataFile` does not exist yet, the plugin falls back to an empty index and
hovers stay inert instead of failing the build.

### What the plugin does

- Registers theme components (`Root`, `CodeBlock/Line`, `CodeBlock/Line/Token`)
  that stamp `data-api-id` on code tokens resolved against the index and mount
  the hover runtime.
- Aliases `docusaurus-plugin-api-hover/data` to your names JSON and injects
  the runtime config (infoUrl, preferPrefixes, languages) through a JSON
  module alias, so it works under both webpack and rspack.
- The `./rehype` export annotates inline code mentions of symbols in prose
  (and takes the id from a link's href when the mention is a link to the
  symbol's page).

### Sites that already provide their own Root

`@theme/Root` composition across plugins is last-registered-wins: if another
plugin in your site's `plugins` array also ships a `Root` and is registered
after this one, its Root is the one Docusaurus renders, and this plugin's
Root (runtime mount + styles) never runs. Register this plugin before such
plugins and mount the runtime yourself at the layout level instead:

```js
import ApiHoverRuntime from 'docusaurus-plugin-api-hover/runtime';
import 'docusaurus-plugin-api-hover/styles';
// e.g. in src/theme/Layout/Provider/index.tsx:
//   composeProviders([/* ... */, ApiHoverRuntime])
```

Both exports ship in the package's exports map; the styles import is required
because the runtime component itself does not import the stylesheet.

### Generating the index

`dataFile` (names JSON) shape:

```json
{
  "ids": ["mypackage.MyClass", "mypackage.MyClass.my_method"],
  "bases": { "mypackage.MySubClass": ["mypackage.MyClass"] },
  "version": "0.1.0"
}
```

`infoUrl` (info JSON) shape:

```json
{
  "mypackage.MyClass": {
    "kind": "class",
    "url": "/api/mypackage/MyClass",
    "signature": "class MyClass(...)",
    "doc": "First line of the docstring summary."
  }
}
```

Resolution rules for names: exact dotted id, import-alias expansion
(`from mypackage import mod` makes `mod.Thing` resolve), unique final segment,
and member lookup through documented base classes. Ambiguous names stay
un-annotated; `preferPrefixes` breaks ties.
